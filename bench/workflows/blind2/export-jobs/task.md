A reporting service at `{{reports_origin}}` builds report exports as background jobs. Export the March 2026 version of four reports and save the finished ones as files. Handle the reports one at a time, in this order: `sales`, `refunds`, `payouts`, `adjustments`.

1. Start a job with the `exports.create` tool, which takes the `report` and the `month` (always `2026-03`) and returns the job's `id`. The service sometimes refuses with "rate limited" (HTTP 429), which means no job was started: repeat the request after waiting 50 milliseconds, at most 2 more times. Do not repeat it after any other failure, and never start a job again because a start succeeded.
2. Watch the job with the `exports.status` tool, which returns its `state` (`queued`, `running`, `done`, or `failed`) and, for a failed job, a `reason`. Ask for the status right after the job was started. While the state is `queued` or `running`, wait and ask again. The first wait is 50 milliseconds, and each wait is twice the one before, but never longer than 200 milliseconds (so the waits are 50, 100, 200, 200, 200, and so on). Add up the waits you have made for this job; when the next wait would bring the total above 1000 milliseconds, stop instead of waiting: the job has timed out. Stop asking about a job as soon as its state is `done` or `failed`, or it has timed out.
3. A job that is `done` has a file. Fetch it with the `exports.download` tool, which takes the job `id` and returns the `lines` of the file. Write the lines to `{{root}}/exports/REPORT.csv`, where `REPORT` is the report's name, with each line followed by `\n`. Do not fetch the file of a job that is not done.
4. A job that failed with the reason `transient` is replaced: start a new job for the same report (step 1) and watch it. A report has at most 3 jobs in all, so after its third failed job the report stops. A job that failed for any other reason ends the report at once. A job that timed out ends the report without a new job.

The outcome of a report is `exported` when one of its jobs was done and its file was written, `timeout` when its last job timed out, and `failed` otherwise.

Return a JSON object with one field, `reports`: for each of the four reports, in the order above, an object `{"report": REPORT, "outcome": OUTCOME, "jobs": [ID, ...], "rows": ROWS}` where `jobs` lists the ids of the report's jobs in the order they were started, and `ROWS` is the number of lines written for an exported report and `null` for the others.
